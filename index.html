1. Introduction to Java Server Pages

In simple words

JSP lets you write a web page that looks like HTML, but you can add small pieces of Java inside it. When a user opens the page, the server runs the Java part, builds HTML, and sends it to the browser. The browser never runs Java — it only shows the final HTML.

Definition (for exam) Java Server Pages (JSP) is a server-side technology used to create dynamic web pages. A JSP file contains HTML (or XML) plus special JSP tags and Java code. The JSP container (like Jasper in Tomcat) translates the JSP into a servlet, compiles it, and runs it. JSP is built on top of the Servlet API and is part of Java EE / Jakarta EE.
What is JSP Why JSP exists Features Architecture Request flow Advantages & disadvantages

Key points to remember

  1. JSP is a view technology — used to show HTML to the user.
  2. Every JSP file is converted into a servlet by the container.
  3. The file extension is .jsp (example: hello.jsp).
  4. JSP runs on the server, not in the browser.
  5. Tomcat uses Jasper as the JSP engine.
  6. JSP can use implicit objects like request, session, out without creating them.

Java Server Pages (JSP) is a server-side technology used to create dynamic web pages. A JSP file looks like HTML, but it can contain Java code, directives and standard tags. The container (Tomcat, GlassFish, Jetty) translates the JSP into a servlet, compiles it, and then that servlet generates HTML for the browser.

1.1 Why JSP was introduced

Servlets are excellent controllers, but writing a full HTML page with out.println("<h1>...") is painful to design and maintain. Designers cannot easily edit Java classes. JSP reverses the idea: HTML is the main file; Java is inserted only where dynamic behaviour is needed.

Presentation

JSP is the View in MVC. Product pages, result sheets, dashboards.

Productivity

Change a heading without recompiling by hand — the container recompiles the JSP.

Reuse

include, JavaBeans, tag libraries and JSTL keep business code out of the page.

1.3 JSP architecture

The browser never executes Java. It only sends HTTP and receives HTML/CSS/JS. The JSP container (Jasper in Apache Tomcat) sits inside the servlet container.

Diagram explanation — Figure 1 (JSP architecture)

  1. Browser (client) — User opens a URL like hello.jsp and sends an HTTP request.
  2. Web server / Tomcat — Receives the request and passes it to the JSP container.
  3. JSP container (Jasper) — Reads the .jsp file, translates it to a servlet, and compiles it.
  4. Generated servlet — Runs Java code, talks to JavaBeans or database if needed.
  5. HTML response — Servlet writes HTML using out object and sends it back to the browser.
  6. Browser displays — User sees the final page. Java code never reaches the browser.

1.4 Request processing (what actually happens)

  1. Client requests http://host:8080/app/hello.jsp.
  2. If hello.jsp was never translated, Jasper creates hello_jsp.java.
  3. Java compiler produces hello_jsp.class. Class is loaded and instantiated.
  4. jspInit() runs once. Then _jspService(request, response) runs for this request.
  5. HTML is collected in a JspWriter buffer and returned as the HTTP response.
  6. Later requests skip translation unless the .jsp file timestamp changed.

Diagram explanation — Figure 2 (Translation pipeline)

  1. Step 1 — JSP file — You write hello.jsp with HTML and JSP tags.
  2. Step 2 — Translation — Jasper creates hello_jsp.java (a servlet source file).
  3. Step 3 — Compilation — Java compiler creates hello_jsp.class (bytecode).
  4. Step 4 — Execution — Container calls _jspService() method for each request.
  5. Step 5 — Output — HTML is sent to the browser as HTTP response.
  6. Note: Translation happens only when the JSP is new or modified. After that, only the compiled class runs (faster).

1.5 Advantages and disadvantages

Advantages

  • Faster UI development than pure servlets.
  • Separation of static design and dynamic logic (especially with beans/JSTL).
  • Portable across any servlet container.
  • Access to entire Java ecosystem (JDBC, mail, JSON, etc.).
  • Session tracking, cookies, filters, listeners already exist.

Disadvantages / cautions

  • Heavy scriptlets make pages unreadable (avoid in production).
  • First request is slower because of translation/compilation.
  • Debugging generated servlet names is less obvious than a hand-written servlet.
  • Mixing business logic in JSP breaks MVC and unit testing.
Exam pointer Write: “JSP is internally converted into a servlet by the JSP container. Therefore JSP can do everything a servlet can, but it is intended as a view technology.”

2. Difference between JSP and Servlet

In simple words

A servlet is a Java class that handles web requests. A JSP is a page file that becomes a servlet automatically. They do the same job inside Tomcat, but JSP is easier for writing HTML. In real projects: servlet = controller (logic), JSP = view (display).

Definition A servlet is a Java program that extends HttpServlet and handles HTTP requests directly. A JSP is a text page (.jsp) that the container converts into a servlet. Both run on the server and produce HTML.

Key points to remember

  1. Servlet = Java file (.java). JSP = page file (.jsp).
  2. Servlet uses doGet() / doPost(). JSP uses _jspService() after translation.
  3. Writing HTML in servlet = many out.println() lines (hard to design).
  4. Writing HTML in JSP = normal HTML with small Java pieces (easy to design).
  5. Both have the same performance after JSP is compiled.
  6. MVC pattern: Servlet → controller, JSP → view.

A servlet is a Java class that handles HTTP. A JSP is a document that becomes such a class. They are not rivals — they are layers. Industry practice: Servlet = controller, JSP = view.

Diagram explanation — Figure 3 (JSP vs Servlet)

  • Left side (Servlet) — Programmer writes Java class. HTML is printed using out.println().
  • Right side (JSP) — Programmer writes HTML page. Java is added only where needed using tags.
  • Same container — Both run inside Tomcat and use request, response, session objects.
  • Same result — Browser receives HTML in both cases.
  • Best practice — Use servlet for control logic; use JSP for showing data to the user.

2.1 Same job, different source

Servlet equivalent

public void doGet(HttpServletRequest req, HttpServletResponse res) {
  res.setContentType("text/html");
  PrintWriter out = res.getWriter();
  String n = req.getParameter("name");
  out.println("<h1>Hello " + n + "</h1>");
}

JSP equivalent

<%@ page contentType="text/html" %>
<h1>Hello <%= request.getParameter("name") %></h1>

After translation the JSP version becomes almost the same servlet. That is why performance is comparable.

2.2 When to use which

Use a servlet for login authentication, file upload control, REST-like endpoints, redirect logic, and as the Front Controller in MVC.
Use a JSP to render HTML: reports, catalogs, dashboards, confirmation pages, error views.

3. Life cycle of JSP

In simple words

JSP life cycle means: what steps happen from the time you write a .jsp file until it serves many user requests and finally gets removed. The main method that runs for every request is _jspService().

Definition JSP life cycle is the sequence of phases a JSP page goes through: translation, compilation, loading, instantiation, initialization (jspInit), request processing (_jspService), and destruction (jspDestroy).

Key points to remember (7 phases)

  1. Translation — .jsp → .java (done by Jasper engine)
  2. Compilation — .java → .class (done by Java compiler)
  3. Loading — Class is loaded into JVM memory
  4. Instantiation — Object of servlet class is created
  5. Initialization — jspInit() runs once
  6. Service — _jspService() runs for every request (most important)
  7. Destruction — jspDestroy() runs when JSP is removed or server stops

The JSP life cycle is the servlet life cycle plus an extra translation phase. Remember seven names for university answers: translation, compilation, loading, instantiation, initialization, request processing, destruction.

Diagram explanation — Figure 4 (Life cycle)

  1. First request — Triggers translation and compilation (slower first time).
  2. jspInit() — Runs one time only, like servlet init(). Use for setup work.
  3. _jspService() — Runs every time a user opens the page. Your scriptlets and HTML go here.
  4. Loop arrow — Many users can call _jspService at the same time (multi-threaded).
  5. jspDestroy() — Runs when JSP is updated, app is undeployed, or server shuts down.
  6. Exam tip: Only _jspService() repeats for each request. Other steps happen once per JSP version.

3.3 Threading

By default a JSP is not single-threaded: many requests share one instance, so instance variables declared with <%! %> must be thread-safe (or avoided). The old attribute isThreadSafe="false" implements SingleThreadModel and is deprecated — do not use it in new work.

4. JSP elements — scriptlets, expressions, declarations

In simple words

JSP elements are special tags where you write Java code inside an HTML page. There are three main types: scriptlet (Java statements), expression (print a value), and declaration (variables and methods at class level). Directives and comments are also JSP elements.

Scriptlet — <% ... %>
Java statements copied inside _jspService(). Used for loops, if-else, and local variables.
Expression — <%= ... %>
Evaluates a Java expression and prints the result. Becomes out.print(...). No semicolon allowed.
Declaration — <%! ... %>
Fields and methods at servlet class level. Used for counters, helper methods, jspInit/jspDestroy.
Comment — <%-- ... --%>
Removed completely. Not visible in browser or in generated servlet output.

Key points to remember

  1. Scriptlet → goes inside _jspService() method.
  2. Expression → becomes out.print(value); — must return a value, no semicolon.
  3. Declaration → becomes class member (field or method) — shared across requests.
  4. HTML text → becomes out.write("...") in the servlet.
  5. Do not write business logic in scriptlets in real projects — use JavaBeans and JSTL instead.

Template text (HTML) is written as-is. Dynamic parts use four scripting elements plus comments. All of them are processed at translation time into Java source.

Diagram explanation — Figure 5 (JSP elements)

  1. HTML / template text — Written directly. Converted to out.write() calls.
  2. Scriptlet <% %> — Java code block placed inside _jspService().
  3. Expression <%= %> — Short way to print a value on the page.
  4. Declaration <%! %> — Placed outside _jspService, at the top of the servlet class.
  5. Directive <%@ %> — Instructions for the translator (page settings, imports).

4.1 Scriptlets

Definition A scriptlet is a fragment of Java that is copied verbatim into _jspService. Use it for loops, if/else, local variables and calling implicit objects.
<%
  int i;
  for (i = 1; i <= 5; i++) {
    out.println(i);
  }
%>

Translated servlet fragment:

int i;
for (i = 1; i <= 5; i++) {
  out.println(i);
}
  • Local variables of scriptlets are request-scoped (new stack frame every call).
  • You may open a block in one scriptlet and close it in another, because they concatenate — this is legal but ugly.
  • Do not declare methods inside scriptlets (methods cannot nest in Java).

5. JSP directives

In simple words

Directives are instructions to the JSP translator. They do not print anything on the page. They tell the container how to build the servlet — for example: import Java packages, set content type, or include another file.

Definition A JSP directive has the syntax <%@ directiveName attribute="value" %>. It is processed at translation time (before the page runs). Three standard directives: page, include, and taglib.

Key points to remember

  1. page directive — Sets page properties: import, contentType, session, errorPage, isErrorPage.
  2. include directive — Pastes another file at translation time (static include). One servlet is created.
  3. taglib directive — Registers custom or JSTL tag libraries (example: c:forEach).
  4. Directives never appear in HTML output — they only affect servlet generation.
  5. errorPage and isErrorPage are page directive attributes used for exception handling.

Directives are messages to the translator. They do not produce output by themselves. Three standard directives: page, include, taglib. 

<%@ directiveName attribute="value" attribute2="value" %>
page directive — <%@ page ... %>
Defines page settings: language, imports, contentType, session, buffer, errorPage, isErrorPage.
include directive — <%@ include file="..." %>
Static include. File content is pasted before compilation. One servlet is generated.
taglib directive — <%@ taglib prefix="c" uri="..." %>
Registers a tag library (JSTL or custom tags) so you can use tags like <c:if>.

6. JSP basic tags (actions) and implicit objects

In simple words

Action tags (like jsp:useBean, jsp:include) run at request time and help with beans, includes, and forwards. Implicit objects are ready-made Java objects (request, session, out, etc.) that Tomcat creates for you — no need to declare them.

Definition — Implicit object An implicit object is a Java object automatically available inside a JSP page. The container creates them in _jspService(). Examples: request, response, session, application, out.

Key points to remember

  1. 9 implicit objects: request, response, out, session, application, config, pageContext, page, exception.
  2. useBean — Creates or finds a JavaBean in page/request/session/application scope.
  3. setProperty — Sets bean values from form/URL parameters.
  4. getProperty — Reads and prints a bean property.
  5. jsp:include — Includes another page at runtime (dynamic).
  6. include directive — Pastes file at compile time (static) — different from jsp:include.
  7. jsp:forward — Sends request to another page; browser URL does not change.

Action tags are XML-style instructions executed at request time. Implicit objects are Java objects the container creates for you inside _jspService.

Diagram explanation — Figure 6 (Action tags & MVC)

  1. Browser — Sends request with form data or URL parameters.
  2. Controller (Servlet) — Validates input, talks to database, stores data in beans.
  3. Model (JavaBean) — Holds data (Student, Cart, Employee). Created with jsp:useBean.
  4. View (JSP) — Displays data using jsp:getProperty or expressions.
  5. include / forward — Reuse header, footer, or send user to another page.

7. Exception handling in JSP

In simple words

When Java code in a JSP fails (bad input, divide by zero, etc.), the user should see a friendly error page — not a scary stack trace. JSP offers three ways: try-catch in scriptlet, errorPage attribute, and web.xml error mapping.

Definition Exception handling in JSP means catching or forwarding errors so the web application responds gracefully. errorPage="error.jsp" on a normal page forwards uncaught errors to an error view. isErrorPage="true" on the error page enables the implicit exception object.

Key points to remember

  1. try-catch — Handle errors inside the same page (best for small, local problems).
  2. errorPage — Set on the page that may fail; names the error JSP to forward to.
  3. isErrorPage="true" — Set on the error JSP; gives access to exception object.
  4. web.xml — Maps HTTP 404, 500, or exception types to error pages for the whole app.
  5. Never show raw stack traces to end users in banking, insurance, or exam portals.

Uncaught exceptions in _jspService would otherwise show a container stack trace to the user. JSP gives three layered techniques: scriptlet try/catch, page-level errorPage, and application-level web.xml.

Diagram explanation — Figure 8 (Exception handling)

  1. Layer 1 — try/catch — Developer catches error in scriptlet and shows a message on the same page.
  2. Layer 2 — errorPage — Uncaught error on pageA.jsp forwards to error.jsp automatically.
  3. Layer 3 — web.xml — Maps error codes (404, 500) or exception types for the entire application.
  4. exception object — On the error page, use <%= exception.getMessage() %> to show details.
  5. Forward vs redirect — errorPage uses server-side forward (same request, URL unchanged).

7.1 try / catch / finally in a scriptlet

Best for recoverable, local problems (parse errors, divide by zero) when the rest of the page can still render.

<%
  try {
    int n = Integer.parseInt(request.getParameter("n"));
    out.println(100 / n);
  } catch (NumberFormatException e) {
    out.println("Please enter digits only");
  } catch (ArithmeticException e) {
    out.println("n cannot be zero");
  } finally {
    /* optional cleanup */
  }
%>

8. Scopes, session tracking and supporting API

In simple words

Scope decides how long data lives and who can see it. Page scope dies when the page finishes. Request scope lasts for one HTTP call. Session scope lasts for one logged-in user. Application scope is shared by all users of the website.

Definition — Scope Scope is the visibility and lifetime of an object stored using setAttribute. JSP has four scopes: page, request, session, and application — from shortest life to longest life.

Key points to remember

  1. page — Data visible only in the current JSP (shortest life).
  2. request — Data shared between servlet and JSP in one request (includes forward/include).
  3. session — Data for one user until logout or timeout (login, shopping cart).
  4. application — Data for all users until server stops (hit counter).
  5. Session tracking uses cookies (JSESSIONID), URL rewriting, or hidden fields.
  6. EL syntax ${sessionScope.user} is the modern way to read scoped data.

JSP + JDBC (how result portals actually load marks)

ICA theory often stops at scriptlets; real apps put JDBC in a DAO class. A textbook scriptlet looks like this (run it on Tomcat with MySQL Connector in WEB-INF/lib — not in the browser simulator): 

<%@ page import="java.sql.*" %>
<%
  Class.forName("com.mysql.cj.jdbc.Driver");
  Connection con = DriverManager.getConnection(
      "jdbc:mysql://localhost:3306/college", "root", "root");
  PreparedStatement ps = con.prepareStatement(
      "SELECT name, marks FROM student WHERE roll=?");
  ps.setString(1, request.getParameter("roll"));
  ResultSet rs = ps.executeQuery();

    out.println(rs.getString("name") + " : " + rs.getInt("marks"));
  } else {
    out.println("Roll not found");

9. Real-life applications of JSP

In simple words

JSP is used wherever a Java web application needs to show dynamic HTML pages — online shopping, bank websites, college result portals, hospital booking, and exam systems. The business logic runs in servlets/beans; JSP only displays the result to the user.

Key points to remember

  1. E-commerce — Product catalog, cart (session), checkout invoice (JSP + beans).

  3. Education ERP — Student login, marks display, hall ticket, feedback forms.
  4. Healthcare / booking — Doctor list, appointment confirmation, search results table.
  5. Modern apps also use Spring MVC / REST + React, but JSP is still taught and used in many Java projects.
